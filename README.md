# hunch

**データから「どう選ぶか」を研究する。**

## 勘とは、素早すぎる思考である

私たちは、ときどき「なんとなく、こっちだと思う」と感じる。理由を聞かれても、うまく説明できない。それでも、なぜか選べてしまう。こうした判断を、私たちは「勘」と呼んでいる。

勘という言葉には、どこか非論理的な響きがある。データや根拠を積み上げて考えることが「論理」であり、理由を説明できない判断が「勘」だと思われがちだ。しかし、本当に勘には論理がないのだろうか。

むしろ勘とは、**素早すぎる思考**なのではないか。

人間は、目の前の情報をただ眺めているわけではない。過去の経験と照らし合わせ、似ているものを探し、違いを見つけ、状況を読み、相手の意図を推測し、これから起こりそうなことを予測している。その処理があまりにも速いため、本人の意識には「考えた過程」が残らず、最後の判断だけが浮かび上がる。

「今日はこの店に入ったほうがいい気がする」
「この人には、この話をしたほうがいい」
「このアイデアは何か面白い」
「たぶん、こちらを選んだほうがいい」

その瞬間、頭の中では大量の情報が処理されているのかもしれない。しかし、その一つ一つを言葉にしている暇はない。だから私たちは、それを「勘」と呼ぶ。

この見方をすると、勘と論理は対立しない。論理とは、思考の過程をゆっくり取り出し、他者にも確認できる形にしたものだと考えられる。一方、勘は、その思考が圧縮され、極端に高速化された状態である。

すると、「データからどう選ぶのか」という問題も変わってくる。

単純に、

**Data → Choice**

なのではない。

その間には、見えない処理がある。

**Data → 認識 → パターン発見 → 類推 → 文脈理解 → 予測 → Choice**

ただし、この処理が速すぎると、本人にはその中間が見えない。

だから勘を研究するとは、勘を否定して論理に置き換えることではない。むしろ、速すぎて見えなくなっている思考を、少しずつ観察することである。

たとえば、ある人が「このデザインは良い」と即座に判断したとする。本人は「なんとなく」としか言えない。しかし後から調べてみると、過去に似た構図を大量に見ていたのかもしれない。あるいは、色のバランス、余白、形の違和感を無意識に検出していたのかもしれない。

勘を記録して、その結果を見る。的中したのか、外れたのか。何を見ていたのか。何を見落としていたのか。どんな経験が影響していたのか。

そうすると、

**勘 → 言語化 → 仮説 → 検証 → ロジック**

という道筋が生まれる。

重要なのは、すべての勘を説明可能なルールにしなくてもよいということだ。勘には、まだ名前のついていない発見や、説明できない創造性も含まれている。

むしろ面白いのは、説明できない判断を「非論理」として捨てるのではなく、**まだ観測できていない思考として扱うこと**である。

AIについて考えるときも、この視点は重要になる。AIが大量のデータから一瞬で答えを出したとき、それを単なる「勘」と呼ぶのか。それとも、その内部で行われている高速なパターン認識や予測を、勘として捉えるのか。

勘とは、神秘的な第六感ではない。

それは、**思考が速すぎて、思考として見えなくなったもの**なのかもしれない。

そして、その「見えない途中」を少しずつ見えるようにすることが、勘を研究するということなのだと思う。

## hunch のタイプ

この見方では、勘のタイプは「何を根拠にしたか」だけではなく、**何の思考処理が高速化されているか**として捉える。

1. パターン認識
2. 類推
3. 差分検出
4. 欠落検出
5. 順序・変化の把握
6. 情報の組合せ
7. 文脈理解
8. 制約による絞り込み
9. 目的からの逆算
10. 経験則
11. 他者モデル
12. 感情予測
13. 美的判断
14. リスク評価
15. 探索先の選択
16. 仮説生成

## ロジックとの関係

hunch は Data → Choice というブラックボックスではなく、**Data → Hunch → Choice** として記録する。

さらに後から、

**Hunch → 言語化 → Evidence → Rule**

へ変換できる可能性がある。

ただし、勘をすべてルール化する必要はない。説明できないままでも、次の探索を生み出す判断として価値を持つ。

## データ構造

最小単位は以下。

    data:
      - observation

    hunch:
      type: pattern
      intuition: "以前うまくいったものに似ている"

    choice:
      selected: A

    reason:
      explicit: false

    evidence:
      - observation

    result:
      outcome: unknown

重要なのは **hunch と reason を分離すること**。

「そう思った」と「説明できる理由」は同じではない。

## hunch の評価

hunch は単純な正解・不正解だけでなく、後から以下を記録する。

- 再現性
- 的中率
- 新規性
- 説明可能性
- 探索価値
- 失敗コスト
- 発見後の学習量

## hunch は選択の中間層

hunch は意思決定エージェント内部の、**「データを見て、次に何をするかを決める圧縮された判断」**として扱う。

**Data → Observe → Hunch → Choice → Action → Outcome → Learning → Hunch 更新**

## Scope

このリポジトリでは特定領域の正解を作るのではなく、

**「データから選択へ飛躍するために、人間やエージェントがどのような勘を使っているか」**

を分類・記録・実験する。
