# hunch

**データから「どう選ぶか」を研究する。**

データと選択のあいだには、必ずしも明示的なルールだけがあるわけではない。

観測されたデータを見て、「なんとなく、こっちだと思う」と飛躍する。
この飛躍を **hunch（勘）** と呼ぶ。

hunch は非論理ではない。経験則・類推・パターン認識・文脈・価値判断などが、短い判断として現れたものとして扱う。

## 問い

Data → Hunch → Choice

データから直接 Choice を出すのではなく、その途中にある「勘」を観察する。

- 何を見ているのか
- 何を無視しているのか
- 何と何を結びつけているのか
- なぜ飛躍できるのか
- その飛躍は再現できるのか
- 後からロジックとして説明できるのか

## hunch のタイプ

### 1. パターン型
過去に見た形との類似から選ぶ。

### 2. 類推型
別の領域・事例を重ねて選ぶ。A で成立した構造を B に適用する。

### 3. 差分型
平均や一般例ではなく、急増・急減・例外・目立つ違いに反応する。

### 4. 欠落型
「あるもの」ではなく「ないもの」から選ぶ。欠損・空白・未説明部分を手掛かりにする。

### 5. 順序型
値そのものより、変化の順番や流れから選ぶ。

### 6. 組合せ型
単独では弱い情報を組み合わせる。A × B になったときに意味を見つける。

### 7. 文脈型
データ単体ではなく、誰が・いつ・どこで・何のために、という状況から選ぶ。

### 8. 制約型
できることより、予算・時間・技術・人員などの「できないこと」から絞る。

### 9. 目的逆算型
Goal → 必要な状態 → 必要な選択 → 現在のデータ、と逆向きに考える。

### 10. 直感型
明示的な根拠をまだ言語化できない「なんとなく」。正解ではなく、後から根拠を発掘する対象として保存する。

### 11. 経験則型
過去の成功・失敗を圧縮した判断。「この条件では起きやすい」という暗黙知。

### 12. 偶然利用型
検索中の脱線、偶然の一致、予想外のデータなどを次の探索に利用する。

### 13. 美的型
数値的最適化ではなく、形・バランス・面白さ・違和感などから選ぶ。

### 14. 感情型
人がどう感じるかを予測して選ぶ。喜び・驚き・退屈・距離感など。

### 15. 他者モデル型
相手の立場・嗜好・行動モデルを想定して選ぶ。

### 16. 探索型
正解を選ぶのではなく、次に調べる価値があるものを選ぶ。

### 17. リスク型
期待値だけでなく、最悪ケース・不確実性・可逆性・失敗コストから選ぶ。

### 18. 飛躍型
既存データから、まだ存在しない仮説を生成する。Data → Hypothesis → Experiment。

## ロジックとの関係

hunch は Data → Choice というブラックボックスではなく、Data → Hunch → Choice として記録する。

さらに後から、Hunch → Evidence → Rule へ変換できる可能性がある。

**勘 → 言語化 → 仮説 → 検証 → ロジック**

すべての hunch をルール化する必要はない。ルール化できない勘も、探索を進めるための重要な情報として残す。

## データ構造

最小単位は以下。

    data:
      - observation

    hunch:
      type: pattern
      intuition: "以前うまくいったものに似ている"

    choice:
      selected: A

    reason:
      explicit: false

    evidence:
      - observation

    result:
      outcome: unknown

重要なのは **hunch と reason を分離すること**。
「そう思った」と「説明できる理由」は同じではない。

## hunch の評価

hunch 自体を単純に正解・不正解で評価するのではなく、後から以下を記録する。

- 再現性
- 的中率
- 新規性
- 説明可能性
- 探索価値
- 失敗コスト
- 発見後の学習量

## hunch は選択の中間層

hunch は意思決定エージェント内部の、**「データを見て、次に何をするかを決める圧縮された判断」**として扱う。

Data → Observe → Hunch → Choice → Action → Outcome → Learning → Hunch 更新

## Scope

このリポジトリでは特定領域の正解を作るのではなく、

**「データから選択へ飛躍するために、人間やエージェントがどのような勘を使っているか」**

を分類・記録・実験する。
